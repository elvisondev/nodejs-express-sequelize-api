# Requisitos do Projeto

## RF01 — Exclusão de registros

- [ ] Implementar requisito.

O cliente não gostaria que registros importantes do sistema,
como as Pessoas, sejam apagados definitivamente do banco de dados.

## RF02 — Listagem de usuários ativos

- [ ] Implementar requisito.

Para deixar a interface mais limpa, o cliente gostaria que
na lista de Pessoas, por padrão, fossem exibidos somente
os usuários ativos.

## RF03 — Validação de dados

- [ ] Implementar requisito.

Foram percebidas algumas falhas de validação dos formulários
por parte do front-end, o que resultou em dados de email
inválidos no banco. É desejável que essa validação não seja
responsabilidade exclusiva do front.

## RF04 — Consulta de matrículas por estudante

- [ ] Implementar requisito.

É importante poder consultar todas as matrículas confirmadas
referentes a estudante X de forma rápida.

## RF05 — Consulta de turmas por intervalo de datas

- [ ] Implementar requisito.

O cliente gostaria de poder consultar as turmas abertas
por intervalo de data, para não receber informações
desnecessárias (como turmas antigas).

## RF06 — Consulta de matrículas e lotação de turmas

- [ ] Implementar requisito.

O cliente quer poder consultar as matrículas por turma
e saber quais delas estão lotadas, para organizar melhor
as matrículas.

## RF07 — Cancelamento automático de matrículas

- [ ] Implementar requisito.

O cliente gostaria que, uma vez que o cadastro de um
estudante fosse desativado, todas as matrículas relativas
a este estudante automaticamente passassem a constar
como “canceladas”.
